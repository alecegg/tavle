# Tasks

Order: library naming and schema mapping (1), the built-in catalog and `Stack` (2), the ```ui converter and generated files (3), custom catalogs in the library and the gate (4). Decisions are in design.md (C1 to C7). The varde host side is the change `pages-catalogs`.

Every task runs in `~/source/<ui>` after `ui-extract` 4.2.

Conventions (same as `openspec/changes/varde-pages-themes/tasks.md` in varde):

- Each task is one unit for one builder: one file group, one check, about 20 minutes. Tags: `(mechanical)` Claude haiku; `(builder)` GPT Terra; `(lead)` Claude Sonnet or Opus.
- Checks: `uv run pytest <paths> -q -p no:cacheprovider` from the named repository root; `npx vitest run <paths>` in `[ui]`.
- `after:` lists tasks that must be done first; "Parallel" lines name tasks with disjoint Owns.
- Owner rule: no skipped, xfailed or deferred failing tests. Browser tasks close every browser in a `finally`, use `mktemp -d -p /var/tmp`, and end with `pgrep -fa chrom` showing no leftover.
- The lead tags `pre-ui-catalogs` before 1.1 (the 4.5 baseline).
- The library keeps zero runtime dependencies: no JSON Schema package; the catalog rules are plain functions.
