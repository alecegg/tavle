# Tasks

Order: green the baseline (0), fast default, fast pre-push and pairwise matrix (1), Python mutation tooling and baseline runs (2), JavaScript mutation tooling and baseline runs (3), static test checks (4), audit by area (5), gates and docs (6), close (7).

Conventions (same as varde's `pages-extract` tasks):

- Each task is one unit for one builder: one owned file set, one check, about 20 minutes. Tags: `(mechanical)` Claude haiku (settled-list edit, text, test-only); `(builder)` GPT Terra (new logic or a judged call); `(lead)` the lead runs it.
- `after:` lists tasks that must be done first. `[mut]` marks a task that runs mutation testing and `[heavy]` one that runs Chromium. At most one `[mut]` or `[heavy]` task runs at a time (7 GB RAM, 4 CPUs, `-n 3` everywhere): each such task lists the previous one in `after:`, so the task numbers give their run order. Every mutation run goes through `scripts/capped.sh` (memory cap and timeout, from task 2.2).
- Each `[mut]` task deletes its own scratch at the end (`just mutate --tag <tag> --clean`, or the Stryker sandbox under `/var/tmp/tmp-alec/stryker-tavle`); its Check proves it.
- Owner rules: never keep a failing, skipped or xfailed test; no suppressions, ceilings, `do_not_mutate` patterns, score exclusions or baseline edits; scratch under `mktemp -d -p /var/tmp` or `$TMPDIR`; start shell commands with `export TMPDIR=/var/tmp/tmp-alec;`.
- Check commands run from `/home/alec/source/tavle`: `uv run --locked pytest <paths> -q -p no:cacheprovider`, `just lint`.
- Audit file format `audit/<area>.md` (in this change folder): a header with the area's source modules (as `--only` globs), tests before and after, and the mutation score before and after; then one row per decision, `| test id | delete, merge or keep | C1 to C5 | evidence |`. Evidence is a mutant name, a `--without` or kill-set result, a `killedBy` listing or a file and line. A `keep` row is only needed for a candidate that C1 flagged and a reason overrides (design D6).
- Survivors (design D7): every non-killed mutant in the area gets exactly one row: killed by a new fast test, `equivalent` with the argument, or `slow-only` with the slow test id from `just mutate --slow` that kills it. No survivor is left unrecorded, and none is hidden by a skip or exclusion. Slow-only mutants stay in the score as survivors.
- Audit task procedure: (1) read the area's survivors from `audit/py-<package>.md` or `audit/js-<group>.md`; (2) for each owned test file apply C1 with the mode chosen in `audit/leave-one-out.md` (Python) or `killedBy` (JS); (3) apply C2 to C5 using `audit/static-scan.md`; (4) delete or merge into one `parametrize`, recording each; (5) handle each survivor as above; (6) rerun the area's tests and mutation score. Removal check: `uv run --locked python scripts/check_audit_removals.py <base> <area>` (task 4.3) exits 0. If the 20 minutes run out, stop after a whole file, record what is done in the audit file, and leave the task unticked for the lead to requeue.
